# Rasmala Smart Display — شاشة جدول العمل اليومي

نظام شاشة عرض مؤسسية لتلفزيون TCL Google TV عبر Yodeck: فيديو يمين + جدول العمل اليومي في الوسط + فيديو يسار، مع لوحة إدارة آمنة بصلاحيات، وتحديث فوري للشاشة دون إعادة تشغيل التلفزيون.

| الرابط | الغرض |
|---|---|
| `https://USER.github.io/REPO/display/` | شاشة العرض العامة — تُضاف إلى Yodeck |
| `https://USER.github.io/REPO/admin/` | لوحة الإدارة — من اللابتوب أو الجوال |

---

## 1) لماذا الشاشة خفيفة ولا تعلق على TCL

هذه أهم قرارات التصميم التي تخص أداء التلفزيون:

| القرار | الأثر على التلفزيون |
|---|---|
| صفحة العرض مكتوبة بـ TypeScript خالص **بدون React** | حجم JavaScript لصفحة العرض نحو 26KB مضغوطة إجمالًا، مقابل ~110KB للوحة الإدارة التي لا تُحمَّل على التلفزيون أبدًا. تحميل وتشغيل أسرع على معالج التلفزيون. |
| عميل Supabase مصغّر (`src/display/lite.ts`) بدل الحزمة الكاملة | حذف ~170KB من الكود غير اللازم للشاشة. |
| **طلب واحد** (`display_snapshot`) يجلب كل البيانات | بدل 5 طلبات منفصلة. |
| تحديث فوري عبر Realtime + استطلاع احتياطي كل 5 دقائق (كل دقيقة عند انقطاع Realtime) | لا إعادة تحميل للصفحة، ولا ضغط على الشبكة. |
| **لا يُعاد رسم إلا الجزء الذي تغيّر** | تعديل حالة مهمة لا يلمس الفيديو ولا الرأس. |
| عنصر `<video>` ثابت لكل جانب، لا يُعاد تحميله إلا إذا تغيّر الرابط | الفيديو يستمر دون انقطاع عند تعديل المهام (تم اختباره). |
| جانب بنسبة 0% يُخفى **ويُحرَّر مفكك الفيديو بالكامل** | عند الحاجة لأقصى خفة: شغّل الجدول فقط. |
| الساعة تتحدث مرة كل دقيقة، لا عدّاد ثوانٍ | لا استهلاك مستمر للمعالج. |
| لا ظلال ثقيلة ولا blur ولا حركة مستمرة | الحركة الوحيدة: تلاشٍ خفيف 0.35 ثانية عند تبديل صفحة المهام. |
| مراقب للفيديو كل 20 ثانية | إذا علِق أو توقف يُعاد تشغيله تلقائيًا. |
| إعادة تحميل ليلية اختيارية (افتراضيًا 4 فجرًا) | تنظيف ذاكرة WebView بعد تشغيل متواصل لأيام. |
| Service Worker + حفظ آخر بيانات محليًا | الشاشة تعمل حتى لو أُعيد تشغيل التلفزيون والإنترنت مقطوع (تم اختباره). |
| الخط Cairo مستضاف مع الموقع | لا اعتماد على Google Fonts أثناء العرض. |

**أكبر عامل في السلاسة هو الفيديو نفسه، وليس الصفحة.** تشغيل فيديوهين معًا هو أثقل عملية على التلفزيون. اتبع قسم «تجهيز الفيديو» أدناه — فيديو 4K أو أفقي كبير داخل قسم ضيق عرضه 480 بكسل يستهلك المعالج دون فائدة.

## 2) لماذا Supabase وليس Firebase

- **قاعدة PostgreSQL مع Row Level Security**: الصلاحيات تُفرض داخل قاعدة البيانات نفسها بلغة SQL قابلة للمراجعة، وليس في الواجهة.
- **المشغلات (Triggers)** تكتب سجل التدقيق تلقائيًا لكل إضافة وتعديل وحذف — لا يمكن تجاوزه من الواجهة.
- المصادقة والتخزين والتحديث الفوري والدوال الخلفية في خدمة واحدة، بخطة مجانية كافية لشاشة واحدة.

**GitHub Pages يستضيف ملفات ثابتة فقط** (HTML/JS/CSS) — لا خادم ولا قاعدة بيانات ولا أسرار. كل ما يحتاج أمانًا موجود في Supabase:

```
[TCL + Yodeck] ──► GitHub Pages /display/ ──► Supabase: display_snapshot() + Realtime
[لابتوب/جوال]  ──► GitHub Pages /admin/   ──► Supabase: Auth + RLS + Storage
                                            └─► Edge Function admin-users (مفتاح الخدمة السري هنا فقط)
```

## 4) الإعداد خطوة بخطوة

### أ) إنشاء مشروع Supabase
1. أنشئ حسابًا في supabase.com ثم **New project**. اختر أقرب منطقة متاحة لكم، واحفظ كلمة مرور قاعدة البيانات في مكان آمن.
2. من **Project Settings ← API** انسخ:
   - **Project URL**
   - **المفتاح العام**: `anon public` أو `Publishable key` (يبدأ بـ `sb_publishable_`).
   - ⚠️ لا تنسخ `service_role` أو `Secret key` إلى أي مكان في المشروع أو GitHub.

### ب) إنشاء قاعدة البيانات
1. افتح **SQL Editor ← New query**.
2. الصق محتوى `supabase/migrations/001_schema.sql` كاملًا واضغط **Run**.
3. (اختياري) الصق `supabase/seed.sql` واضغط **Run** لإضافة جدول تجريبي لليوم وقالب «يوم عمل اعتيادي».

### ج) المستخدم الأول (المدير العام)
1. **Authentication ← Sign In / Providers**: عطّل **Allow new users to sign up**. (لا أحد يسجّل نفسه؛ المدير هو من يضيف المستخدمين.)
2. **Authentication ← Users ← Add user ← Create new user**: أدخل بريدك وكلمة مرور قوية، وفعّل **Auto Confirm User**.
3. **أول مستخدم يُنشأ في النظام يصبح «مديرًا عامًا» تلقائيًا**. للتحقق، شغّل في SQL Editor:
   ```sql
   select email, role, is_active from public.profiles;
   ```
   للترقية يدويًا عند الحاجة:
   ```sql
   update public.profiles set role = 'admin', is_active = true where email = 'you@example.com';
   ```

4. شغّل أيضًا `supabase/migrations/002_slides.sql` (يضيف ميزة عرض الشرائح من PDF). آمن لإعادة التشغيل.

### د) نشر دالة إدارة المستخدمين (Edge Function)
إضافة المستخدمين وتعطيلهم وتغيير كلمات مرورهم تتطلب مفتاح الخدمة السري، لذلك تتم في دالة على خوادم Supabase وليس في المتصفح.

**الطريقة 1 — من لوحة Supabase (الأسهل):**
1. **Edge Functions ← Deploy a new function ← Via Editor**.
2. الاسم: `admin-users` (بالضبط).
3. الصق محتوى `supabase/functions/admin-users/index.ts` واضغط **Deploy**.
4. من إعدادات الدالة: أوقف **Verify JWT** (الدالة تتحقق بنفسها من هوية المستخدم وأنه مدير عام نشط؛ إيقاف التحقق المسبق يتجنب مشاكل التوافق مع مفاتيح JWT الجديدة).

**الطريقة 2 — سطر الأوامر:**
```bash
npx supabase login
npx supabase link --project-ref YOUR-PROJECT-REF
npx supabase functions deploy admin-users --no-verify-jwt
```

مفتاح الخدمة متاح تلقائيًا داخل الدالة باسم `SUPABASE_SERVICE_ROLE_KEY`. إن ظهرت رسالة «مفتاح الخدمة غير مضبوط»، أضفه من **Edge Functions ← Secrets** باسم `SERVICE_ROLE_KEY`.
اختياري: أضف سرًا باسم `ALLOWED_ORIGIN` بقيمة `https://USER.github.io` لتقييد الوصول لموقعك فقط.

### هـ) النشر على GitHub Pages
1. أنشئ مستودعًا جديدًا على GitHub (مثلًا `rasmala-smart-display`). GitHub Pages مجاني للمستودعات **العامة**؛ للمستودع الخاص تحتاج خطة GitHub مدفوعة. المستودع العام آمن هنا لأنه لا يحتوي أي سر.
2. ارفع الملفات:
   ```bash
   cd rasmala-smart-display
   git init && git add . && git commit -m "Rasmala Smart Display"
   git branch -M main
   git remote add origin https://github.com/USER/rasmala-smart-display.git
   git push -u origin main
   ```
3. في المستودع: **Settings ← Pages ← Source: GitHub Actions**.
4. **Settings ← Secrets and variables ← Actions ← Variables ← New repository variable**:
   - `VITE_SUPABASE_URL` = رابط المشروع
   - `VITE_SUPABASE_ANON_KEY` = المفتاح العام فقط
   - `BASE_PATH` (اختياري) — يُحسب تلقائيًا من اسم المستودع. ضع `/` إذا استخدمت نطاقًا خاصًا.
5. **Actions ← Deploy to GitHub Pages ← Run workflow** (أو أي `git push` لاحق ينشر تلقائيًا).
6. بعد دقيقتين تقريبًا:
   - العرض: `https://USER.github.io/rasmala-smart-display/display/`
   - الإدارة: `https://USER.github.io/rasmala-smart-display/admin/`

المساران مجلدان حقيقيان في الموقع المنشور، لذلك يعملان على GitHub Pages دون أي إعدادات إعادة توجيه، ورابط `/display` بدون الشرطة الأخيرة يُحوَّل تلقائيًا.

### و) التشغيل المحلي (للتطوير)
```bash
npm install
cp .env.example .env.local     # ثم أدخل القيم
npm run dev                    # http://localhost:5173/display/ و /admin/
npm run build                  # فحص الأنواع + بناء dist/
```
قبل ضبط المفاتيح تعرض صفحة العرض بيانات تجريبية مع شارة «وضع تجريبي» لتتمكن من رؤية التصميم.

## 5) ربط الشاشة بـ Yodeck على TCL Google TV

### ما الذي تحققت منه في وثائق Yodeck (أكتوبر 2026)
- تطبيق Yodeck من **Google Play** يعمل على أجهزة Android TV الاستهلاكية ومنها **TCL**، ويتطلب Android 6 أو أحدث، و500MB مساحة حرة، وحساب Google مسجلًا على الجهاز.
- **الخطة المجانية**: شاشة واحدة مجانًا بميزات خطة Basic، وتبقى مجانية فقط ما دام الحساب فيه شاشة واحدة.
- تطبيق Play Store **يستخدم محرك الويب** للعرض، وصفحات الويب مدعومة.
- **قيود تطبيق Play Store** حسب Yodeck: لا يفتح تلقائيًا بعد إعادة تشغيل الجهاز، ولا يدعم وضع Kiosk، ولا ضبط المنطقة الزمنية من البوابة، ولا «السكربتات المخصصة على صفحات الويب».
  - «السكربتات المخصصة» هنا تعني ميزة **Web Scripting Engine** في Yodeck (أوامر تحقنها Yodeck في الصفحة)، وليس الكود الخاص بالصفحة نفسها. صفحتنا لا تحتاج تلك الميزة. ومع ذلك **اختبر على جهازك** بالخطوات أدناه قبل الاعتماد النهائي.
- لصفحات الويب: Yodeck تنصح باستخدام صفحة مهيأة لدقة الشاشة إذا لم يعمل التكبير كما يجب — صفحتنا تتكيف تلقائيًا مع أي دقة.

> لا أستطيع ضمان أن كل طراز TCL يعمل بنفس الطريقة؛ الأجهزة تختلف في معالجها وإصدار Android System WebView. لذلك صُمم النظام مع خطة بديلة (ب) أدناه.

### الطريقة (أ): الشاشة كاملة كصفحة ويب واحدة
1. على التلفزيون: Google Play ← ثبّت **Yodeck** ← افتحه واسمح بكل الأذونات، سيظهر رمز تسجيل من 9 أرقام.
2. حدّث **Android System WebView** من Google Play (يحل معظم مشاكل الشاشة السوداء وتشغيل الفيديو).
3. اضبط المنطقة الزمنية للتلفزيون على **الرياض** من إعدادات Android (الشاشة نفسها تأخذ الوقت من الخادم، لكن جدولة Yodeck تعتمد على وقت الجهاز).
4. في بوابة Yodeck: **Screens ← + Add Screen ← Android Player** وأدخل الرمز.
5. **Media/Web Pages ← Add Web Page**: الصق رابط `.../display/`. **لا تفعّل** «Refresh Web Page» — الصفحة تتحدث ذاتيًا، والتحديث الدوري يعيد تحميل الفيديوهات بلا داعٍ.
6. أضف صفحة الويب إلى Playlist أو Layout بملء الشاشة، وعيّنها للشاشة، ثم اضغط **Push to Players**.

### الطريقة (ب) — الأخف والأكثر ثباتًا: الفيديو من Yodeck والجدول من صفحتنا
إذا لاحظت أي تقطيع مع فيديوهين داخل صفحة الويب، اجعل Yodeck يشغّل الفيديوهات بمشغله الأصلي (يحفظها على الجهاز ولا يعيد تنزيلها):
1. ارفع الفيديوهين إلى مكتبة Yodeck.
2. أنشئ **Layout** بثلاث مناطق متجاورة بنفس النسب (مثلًا 480 + 960 + 480 بكسل على 1920).
3. المنطقة الوسطى: Web Page برابط `.../display/?videos=0` — هذا الوضع يعرض الجدول فقط بعرض كامل ولا يحمّل أي فيديو.
4. المنطقتان الجانبيتان: الفيديوهات.
5. ملاحظة من Yodeck: على Android تُرسم صفحات الويب دائمًا فوق المحتوى الآخر في نفس المنطقة؛ هذا لا يؤثر هنا لأن المناطق غير متداخلة. وإذا تقطع الفيديو داخل Layout، تنصح Yodeck بتقليل عدد المناطق.
6. تحقق من توفر Layouts في خطتك من البوابة (خطة Basic تتضمن تخطيطات المناطق حسب صفحات الأسعار، لكن تأكد من حسابك).

### إعادة التشغيل وانقطاع الكهرباء
- تطبيق Yodeck من Play Store **لا يفتح تلقائيًا** بعد انقطاع الكهرباء — يجب فتحه يدويًا. للتشغيل التلقائي ووضع Kiosk استخدم إعداد **APK v2 Production Setup** من Yodeck (يتطلب خطوات تقنية عبر ADB من دليلهم).
- انقطاع الإنترنت: الشاشة تبقى تعرض آخر جدول محفوظ مع ملاحظة صغيرة «غير متصل» في الأسفل، وتعود للتحديث تلقائيًا عند عودة الاتصال، دون أي تدخل.
- إعادة تشغيل التلفزيون أثناء انقطاع الإنترنت: الصفحة تفتح من الذاكرة المحلية وتعرض آخر جدول لنفس اليوم.

### دقة 1920×1080
- اضبط مخرج التلفزيون على 1080p من إعدادات العرض في Android.
- كثير من أجهزة Android TV تعرض الويب بدقة منطقية 960×540 مع مضاعف 2؛ الصفحة تحسب مقاس الخط من ارتفاع الشاشة وعرض القسم الأوسط، فتبدو متطابقة في الحالتين.
- إذا بدا الخط كبيرًا أو صغيرًا على جهازك، أضف للرابط `?fs=0.9` أو `?fs=1.1`.

### معاملات الرابط المتاحة
| المعامل | الأثر |
|---|---|
| `?videos=0` | الجدول فقط بعرض كامل، لا تحميل لأي فيديو |
| `?fs=1.1` | تكبير/تصغير الخط (0.6 – 1.6) |
| `?demo=1` | بيانات تجريبية للعرض دون قاعدة بيانات |

### التشغيل التلقائي للفيديو
الفيديو مكتوم الصوت ومعه `playsinline` و`autoplay`، وهذا ما تسمح به متصفحات Chromium/WebView دون تفاعل. إذا لم يعمل:
1. حدّث Android System WebView وتطبيق Yodeck من Google Play.
2. تأكد أن الملف MP4 بترميز H.264 (توصية Yodeck نفسها: MP4، H.264، 30 إطارًا).
3. افتح رابط الفيديو مباشرة في متصفح على اللابتوب؛ إذا طلب تسجيل دخول أو حمّل الملف بدل تشغيله فهو ليس رابطًا مباشرًا صالحًا.
4. استخدم الطريقة (ب).

## 6) تجهيز الفيديو (أهم خطوة للسلاسة)

| الإعداد | القيمة |
|---|---|
| الصيغة | MP4، H.264 (High)، yuv420p |
| الأبعاد | بمقاس القسم بالضبط: 25% ← **480×1080**، 20% ← **384×1080**، 30% ← **576×1080** |
| الإطارات | 30 إطار/ثانية |
| معدل البت | 2–4 Mbps |
| الصوت | بدون (الشاشة مكتومة أصلًا) |
| الحجم | أقل من 50MB (حد الرفع في خطة Supabase المجانية) |
| faststart | نعم (يبدأ التشغيل قبل اكتمال التنزيل) |

باستخدام السكربت المرفق (يتطلب ffmpeg):
```bash
./scripts/encode-video.sh input.mp4 right-side.mp4 25
```
أو مباشرة على Windows/Mac:
```bash
ffmpeg -i input.mp4 -vf "scale=480:1080:force_original_aspect_ratio=increase,crop=480:1080,fps=30" -c:v libx264 -profile:v high -level 4.0 -pix_fmt yuv420p -preset slow -crf 23 -maxrate 3M -bufsize 6M -movflags +faststart -an right-side.mp4
```
الفيديو المرفوع من لوحة الإدارة يُحفظ باسم فريد مع تعليمات تخزين مؤقت لمدة سنة، فلا يعيد التلفزيون تنزيله في كل مرة.

## 6-ب) عرض شرائح PDF بدل الفيديو (الأخف على التلفزيون)

من **لوحة الإدارة ← الفيديوهات**، في أي قسم اختر **«عرض شرائح (PDF / صور)»** ثم **«رفع ملف PDF»**:
- يتحول الـ PDF إلى صور **داخل متصفحك** (حتى 40 صفحة، وحتى 40MB) ثم تُرفع الصور فقط.
- رتّب الصفحات بالأسهم أو احذف ما لا تريده، واختر مدة كل شريحة (5–60 ثانية)، ثم **حفظ ونشر**.
- يمكنك أيضًا **«إضافة صور»** (PNG/JPG/WEBP) بدل الـ PDF أو بجانبه.
- على الشاشة: صورتان فقط تتبادلان بتلاشٍ خفيف — **لا يوجد فك ترميز فيديو إطلاقًا**، فهو أخف خيار ممكن.
- أفضل تصميم للصفحات: طولي بنسبة القسم (480×1080 عند تقسيم 25/50/25). صفحات A4 الطولية تظهر كاملة مع هامش كحلي أعلى وأسفل.
- لتوفير مساحة التخزين: زر **«حذف كل غير المستخدم»** أسفل الصفحة يحذف الصور القديمة.

حمايات إضافية:

- لوحة الإدارة ترفض الفتح داخل إطار في موقع آخر، والصفحات المنشورة تحمل سياسة أمان محتوى (CSP).

## 8) قائمة الاختبار بعد النشر

**قاعدة البيانات والدخول**
- [ ] `select email, role from profiles;` يُظهر حسابك بدور `admin`.
- [ ] الدخول بكلمة مرور خاطئة يعطي رسالة عربية واضحة.
- [ ] الدخول الصحيح يفتح الرئيسية مع ملخص اليوم.

**المهام**
- [ ] إضافة مهمة بوقت نهاية قبل البداية ← رسالة خطأ ولا تُحفظ.
- [ ] إضافة مهمة صحيحة ← تظهر على شاشة العرض خلال ثوانٍ دون لمس التلفزيون.
- [ ] مربع الاختيار يحوّلها «مكتملة» وإعادة النقر تعيد فتحها.
- [ ] الحذف يطلب تأكيدًا، و«إلغاء» لا يحذف.
- [ ] الأسهم تغيّر الترتيب، و«ترتيب حسب الوقت» يرتب الكل.
- [ ] «إخفاء عن الشاشة» يخفيها من العرض فقط.
- [ ] نسخ جدول الأمس إلى الغد، وحفظ قالب، وتطبيقه على يوم آخر.
- [ ] تعديل الأولويات والملاحظات ثم «حفظ ونشر».

**الشاشة على التلفزيون**
- [ ] التاريخ واليوم والهجري والساعة صحيحة بتوقيت الرياض.
- [ ] فترات الصلاة والاستراحة بلون مختلف، والمهمة الجارية مميزة بـ«الآن».
- [ ] أضف 20 مهمة ← تظهر «صفحة 1 من 3» وتتبدل تلقائيًا، دون تمرير أو قص.
- [ ] الفيديوهان يعملان مكتومين ومتكررين، ولا ينقطعان عند تعديل مهمة.
- [ ] ضع رابط فيديو خاطئًا ← تظهر الصورة الاحتياطية أو اسم المؤسسة.
- [ ] افصل الإنترنت ← تبقى البيانات مع «غير متصل»؛ أعده ← تختفي الملاحظة وتتحدث البيانات.
- [ ] غيّر التقسيم إلى 20/60/20 من الإعدادات ← يتغير على الشاشة دون إعادة تشغيل.
- [ ] راقب الشاشة 8 ساعات متواصلة دون تجمّد.

**الصلاحيات**
- [ ] أنشئ «مشاهد» ← يرى كل شيء بلا أزرار تعديل، وصفحة المستخدمين «غير مصرح».
- [ ] أنشئ «محرر» بدون صلاحية فيديو ← صفحة الفيديو للقراءة فقط.
- [ ] عطّل المحرر وهو مسجّل دخول ← تفشل عملياته فورًا.
- [ ] سجل التدقيق يعرض كل ما سبق باسم من قام به ووقته.

| الخدمة | المجاني | متى تحتاج الدفع |

**تنبيهات مهمة:**
- **إيقاف المشروع المجاني**: Supabase توقف المشاريع المجانية بعد أسبوع من عدم النشاط. الشاشة تتصل بالقاعدة طوال اليوم، وهذا عادةً يُعد نشاطًا، لكني لم أتحقق من تعريف Supabase الدقيق «للنشاط». إن توقف المشروع ستعرض الشاشة آخر جدول محفوظ، ويلزم استعادته يدويًا من لوحة Supabase. للتشغيل الإنتاجي دون أي مخاطرة: خطة Pro.
- **استهلاك البيانات**: بيانات الجدول صغيرة جدًا (أقل من 50MB شهريًا). الاستهلاك الحقيقي من الفيديو: فيديوهان بحجم 20MB لكل منهما يُنزّلان مرة يوميًا ≈ 1.2GB شهريًا، ضمن حد 5GB. إذا كانت ذاكرة WebView في جهازك صغيرة وتعيد التنزيل كثيرًا، فالطريقة (ب) في Yodeck تحل المشكلة لأن Yodeck يحفظ الفيديو على الجهاز.
- لا توجد تكاليف أخرى: لا خادم ولا نطاق إلزامي.

## 10) حل المشاكل الشائعة

| المشكلة | الحل |
|---|---|

## 11) ما الذي اختُبر فعليًا قبل التسليم
- ملف SQL شُغّل على PostgreSQL 16 مرتين متتاليتين (قابل لإعادة التشغيل)، مع اختبار كل دور: مجهول، مشاهد، محرر، محرر فيديو، مدير، حساب معطّل، حماية آخر مدير.
- تشغيل كامل محليًا مع **Supabase Auth (GoTrue) وPostgREST الحقيقيين**: الدخول، إنشاء المستخدمين عبر الدالة، الحظر الفوري للحساب المعطّل.
- 17 اختبار متصفح آلي للوحة والشاشة: الإضافة، التحقق من الوقت، الإكمال، الأولويات، الترتيب، الحذف بتأكيد، نسخ يوم، التقسيم، صلاحيات المشاهد على الجوال.
- الشاشة: الصفحات التلقائية على 1080p و720p دون تمرير، الانقطاع والعودة، الإقلاع دون إنترنت، استمرار الفيديو دون إعادة تحميل، الصورة البديلة عند تعطل الرابط.

**لم يُختبر محليًا** (يحتاج مشروع Supabase حقيقي): Realtime (الشاشة تعمل بدونه بالاستطلاع الاحتياطي)، رفع الملفات إلى Storage، وتشغيل الدالة على Deno الخاص بـ Supabase (اختُبر نفس كودها على Node مع Auth حقيقي). وبالطبع التشغيل الفعلي على جهاز TCL — استخدم قائمة الاختبار أعلاه.
